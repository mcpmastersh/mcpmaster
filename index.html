02 Code mode

Agents write a snippet. Only the answer comes back.

The agent searches, reads a schema, calls the tool and returns just the part it wants. The full API response never reaches its context.

  • QuickJS sandbox compiled to WebAssembly
  • No network, filesystem or host access, only your tools
  • Bounded in time (30 s), memory, calls and result size
snippet.ts · run by the agent
const { items } = await tools.search({ query: "open issues" });
const path = items[0].path;   // "github_list_issues"
const { inputSchema } = await tools.describe.tool({ path });
const issues = await tools[path]({
  repo: "acme/api",
  state: "open",
});
return issues.map((i) => ({
  title: i.title,
  url: i.html_url,
}));  // only this goes back
03 Guardrails

Decide what agents can reach. Even tools that don't exist yet.

Block rules, read-only and review are evaluated on every listing and every call. A github_delete_* rule hides a delete endpoint the moment a sync brings it in.

  • Per-tool switches and glob rules with live match counts
  • --read-only: only GET, queries and read-only MCP tools
  • --hide-new-tools: new tools wait for your review

Built for agents

setup-prompt.txt
Set up mcpmaster so every tool I use is behind one MCP endpoint.

1. Install it (needs Node 20+; no sudo):
   curl -fsSL https://raw.githubusercontent.com/mcpmastersh/mcpmaster/main/install.sh | MCPMASTER_SKILL=1 sh
2. Run `mcpmaster status`, then `mcpmaster connect` and apply the snippet for my client
   (for Claude Code: `mcpmaster connect claude-code | sh`).
3. Read the skill it saved (~/.claude/skills/mcpmaster/SKILL.md) or run `mcpmaster help`.
4. Ask me which API, GraphQL endpoint or MCP server to add first, then `mcpmaster add <url> --name <slug>`
   and show me `mcpmaster list`.

Rules:
- Pass credentials by variable name (--token-env) or stdin (--token-stdin). Never as an argument, never ask me to paste one here.
- The endpoint advertises one `execute` tool on purpose. Do not try to list every tool instead.
- Do not turn on private-network access without asking me and saying why.
- Do not guess flags. Run `mcpmaster --help` and use what it lists.
- If a step fails, quote what it printed and give me the next thing to try.
Security

Built as if the browser tab next door is hostile.

mcpmaster runs on your machine. Credentials are used, never shown, and every outbound call takes one audited path.

Loopback only

Binds to 127.0.0.1 and rejects any other Host header, which blocks DNS rebinding.

Token on every call

The UI API and HTTP endpoint require your local token, passed in the URL fragment. Strict CSP, no cross-origin writes.

Used, never shown

Credentials live in an owner-only file or an env var. If an API echoes one back, it's removed before the agent sees it.

One egress path

Pins the validated DNS answer, never follows redirects, caps time and size. Private networks stay blocked until you opt in.

No stale OAuth clients

OAuth state is kept per integration, not per URL. Each sign-in registers a fresh client; sign-out deletes all of it.

Consent stays local

Callbacks land on 127.0.0.1 with a single-use state from the last 10 minutes. PKCE always, https token URLs only.

FAQ

Questions, answered.

Anything else? Open an issue on GitHub.

What is mcpmaster?

A local MCP server that wraps every API and MCP server you use and serves them all through one connection. Add an OpenAPI spec, a GraphQL endpoint, a remote MCP server or a local stdio command, and every connected agent can use it.

Why only one execute tool?

Loading every schema up front can cost hundreds of thousands of tokens. With code mode the agent searches for tools and returns only what it needs. If your client can't run code, mcpmaster settings tools all lists every tool individually.

Where are my credentials stored?

In ~/.mcpmaster/secrets.json with owner-only permissions, or read from an environment variable. The CLI and UI never display them, and they're stripped from any response that echoes them. Pass them with --token-env or --token-stdin, never as an argument.

How is this different from mcpmaster Cloud?

Self-hosted is the open-source core. Cloud runs the same engine and adds a hosted endpoint, team workspaces, private workspaces behind OAuth, Agent Secrets, crawling, a chat widget and an audit trail. You can use both at once.

How do I upgrade?

Run the installer again, or mcpmaster update. It pulls the newest version from npm, restarts the background server and keeps your integrations and credentials.
